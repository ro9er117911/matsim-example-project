# Tamsui Tsunami Evacuation - Deployment & Testing Plan

## 1. System Requirements (Resource Planning)

Running a large-scale evacuation simulation (estimated ~200,000 agents for Tamsui/North Coast) requires significant computational resources.

| Component | Minimum Requirement | Recommended | Notes |
| :--- | :--- | :--- | :--- |
| **RAM** | 16 GB | **32 GB+** | MATSim keeps the whole network and population in RAM. Evacuation modules add overhead. |
| **CPU** | 4 Cores | **8 Cores+** | MATSim parallelizes the mobility simulation (QSim). More cores = faster iterations. |
| **Disk** | 50 GB | **100 GB (SSD)** | Output events files are huge (GBs per iteration). SSD is crucial for I/O speed. |
| **Java** | JDK 21 | JDK 21 | Project standard. |

> [!TIP]
> **Memory Setting**: Always run with `-Xmx` set to ~80-90% of your available physical RAM (e.g., `-Xmx28g` on a 32GB machine).

## 3. Investigating the "Weird Network" (NE Corner Node)

**Symptom**: "All nodes connect to a strange point in the top-right (Northeast)."

**Explanation**:
This is **Expected Behavior** of the Evacuation Module, not a bug.
*   The module works by defining a "Safe Zone" which is "Everything outside the Evacuation Area".
*   To model this mathematically, it creates a single **Super-Node** (infinite capacity sink).
*   It cuts your network at the boundary of your `evacuation_area.shp`.
*   All boundary links are connected via "virtual links" to this one Super-Node.
*   If the Super-Node's coordinates (0,0 or max_x, max_y) are far from your map, lines will stretch across the screen.

**How to Verify**:
1.  Open the generated `output_network.xml.gz` in VIA or QGIS.
2.  Look for a node with ID like `super_node` or usually a very high ID number.
3.  Check its coordinates.
4.  If the simulation runs and agents "leave" the area, the network is functional.

## 4. Operational Plan (Headless Execution)

For the final large-scale run, **do not use the GUI**. The GUI consumes memory and can freeze map rendering.

1.  **Prepare Config**: Use the GUI *once* to set up the scenario, then click "Save Config" (or find `config.xml` in the output folder after a dry run).
2.  **Move Config**: Copy the generated `config.xml` to your test folder.
3.  **Run Headless**:
    Use the provided `run_headless.sh` script.

    ```bash
    ./run_headless.sh ./output/config.xml
    ```

## 5. Troubleshooting Guide

| Error | Likely Cause | Solution |
| :--- | :--- | :--- |
| `OutOfMemoryError: Java heap space` | RAM limit too low | Increase `-Xmx` in `run_headless.sh`. |
| `IllegalArgumentException: Coordinates...` | Coordinate System Mismatch | Ensure input OSM/Shapefiles are in **EPSG:3826** (TWD97). MATSim config must match. |
| `IndexOutOfBoundsException` in Analysis | Empty Events File? | Check if the simulation actually produced events (did agents move?). |
| Network looks like a "Star" | Super-Node Visualization | Ignore visualization artifact; check if agents flow *out* of the boundary links. |
