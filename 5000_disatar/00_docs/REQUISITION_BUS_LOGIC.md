# 災難撤離公車徵調邏輯 (Bus Requisition Logic)

本文件說明在「淡水海嘯撤離模擬」中，如何從廣大的 GTFS 資料集中篩選出「最可能被徵調為疏散接駁車」的公車路線。

## 1. 篩選核心目標
政府在災難發生時，會優先徵調具有規模、且在災區周邊有即時運量的公車資源。篩選分為三個維度：

### A. 營運商維度 (Operator Strategy)
我們將營運商分為兩個優先權等級：
- **P1 (核心徵調)**：
  - **區公所接駁車** (如：淡水區公所)：直接受政府指揮。
  - **區域在地客運** (如：淡水客運、指南客運)：在淡水設有場站，調度速度最快。
- **P2 (區域支援)**：
  - **大型區域客運** (如：首都客運、臺北客運、三重客運、大都會客運)：具有大規模車隊，可跨區支援。

### B. 空間維度 (Spatial Bounds)
- **淡水災難區 (Tamsui Zone)**：路線必須在淡水區內（lon: 121.35~121.65, lat: 25.10~25.25）至少有一個停靠站，確保車輛在物理上可供災區使用。

### C. 時間維度 (Temporal Window)
- **撤離黃金時間 (03:00 ~ 09:00)**：僅保留在此時段內有發車或運行記錄的班次。這排除掉無關的深夜或中午後路線，使模擬聚焦於撤離高峰期。

---

## 2. 模擬場景中的交互作用 (Multi-modal Interactions)
篩選後的公車將與其他模式共同運行，產生以下現象：
- **公車 vs 汽車**：公車與私家車共用道路空間，在壅塞路段（如關渡大橋、台2線）會互相卡住，反映真實的延誤。
- **公車 vs 捷運**：公車作為接駁工具，將代理人送往捷運站（如淡水站、紅樹林站）進行大運量轉運。
- **公車 vs 步行**：代理人需步行至公車站，且公車停靠時會產生上下車時間（Boarding/Alighting time）。

---

## 3. 執行指令 (Execution)
使用專用腳本 `scripts/filter_bus_routes.py` 進行處理：
```bash
python3 scripts/filter_bus_routes.py \
    --input <原始GTFS> \
    --output <徵調公車GTFS> \
    --priority 2 \
    --time "03:00:00,09:00:00"
```
